# Explicit source binding in compiled review

These tests reuse the separately recorded exact native/Rust source-binding
fixture via `RENDERED_ROLE_BINDING_FIXTURE`. Missing private inputs are explicit
fixture skips, never a positive native acceptance result.

The workspace, canonical source-report admission, accepted compile capture and
ticket, navigation policy, role-binding service and controller are real. Native
PDF character/query results are replayed from the independently executed
fixture. Layout/evaluation ports are deliberately modeled and emit no normative
Pass/Fail. The tests prove controller ownership/correlation guards, not fresh
renderer measurement, standards compliance, UI or offline acceptance.

The optional fifth controller constructor argument enables explicit
`BindSourceEventAsync(report, eventIndex, ct)`. The controller owns annotation
IDs and retains only known exact issued Proof.Annotation references. Author
labels remain separate; cloned, foreign or stale machine labels cannot be
confirmed through SelectAnnotations. SourceBindings exposes readonly range
metadata. RemoveAnnotation removes stale rows without reconfirming the rest;
clearing all rows is always safe.

Binding and review share foreground admission. Observable actual returned
tasks retain the slot after logical cancellation until they settle. Existing
query adapters independently retain their hidden physical slot after public
logical cancellation; the controller does not own unseen query cleanup.

Source report/profile/root/work type, accepted compile ticket, complete captured
text preimages and imported bytes remain bound. Review re-verifies issued
proofs before and across asynchronous inspection/evaluation, and requires the
later layout runtime and native scalar indexes to match. Failed analyzer-epoch
verification retires the issuance; cancelling an unrelated review preserves
otherwise valid source labels.

Source headingText remains a character range and cannot act as a section/body
container. GlyphInkMeasured remains false. Controller support is not application
registration or browser acceptance; root owns those integration gates.
