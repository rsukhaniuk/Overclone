# Opt-in Xe native SyncTeX and XDV7 geometry

This is a separate native source candidate, not an enabled application profile.
The existing `prepare.py`, `build.py`, `runtime.cpp`, old format and production
Xe resources retain their old behavior. Root owns phase13, a new closed profile,
actual worker budgets/correlation and source/PDF browser acceptance. No query,
C#/Rust/product-JS/pin/renderer or physical-layout changes belong to this package.

## Genuine producer and format

`prepare-maps.py` verifies `maps-inputs.json`, runs the existing default handwritten
port preparation privately, then uses real TIE, **OTANGLE** and Web2C/fixwrites/
splitup/makecpool. It applies upstream Xe-specific SyncTeX definitions, memory and
recording changes in the upstream xetex.am/synctex.am order. It does not use pdfTeX
node offsets or edit generated C. The retained WEB is XeTeX0.999992; the unrelated
later tracingstacklevels change conflicts with its start_input preimage and is
not part of this candidate. A narrow shared tex.ch compatibility patch and the
owned maps-abi.ch preserve that port's base-TeX/logging ABI. Duplicate gzFile in
old Xe definitions is removed because the supplied common.defines owns it.

If the native OTANGLE binary is absent, bootstrap the **supplied**
omegaware/otangle.web + otangle.ch with the supplied TANGLE, Web2C and fixwrites;
compile that generated helper against the supplied native generator libraries.
Do not silently use ordinary TANGLE for the Xe WEB. Exact bootstrap commands and
input/output/tool hashes accompany the handoff. No acquisition or Makefile runs.

The producer uses the actual Xe UTF16-pool `gettexstring` conversion and actual
opened-source stack. It translates only the fixed `/work/` virtual mount prefix
to the complete captured relative spelling, preserving all remaining bytes.
It does not scan source, match basenames, normalize Unicode or resolve traversal.
Resource-only `/tex/` names remain resource names. This preserves the existing
relative-only query ABI1, without broadening its admission. The first absolute
native-name probe is retained, not counted as final query-WASM compatibility.
Non-BMP filename support remains the existing R1 gap: main names are rejected;
emoji/combining source comments do not prove filename or shaped-ink support.

All affected C/C++ engine/header units are recompiled. The old format is NOT used
with this new node/string layout. Actual INITEX produces a genuine new xelatex.fmt
from the supplied kernel/ini/resources. Its exact bytes, engine, actual generating
inputs and fixture clock are bound in receipts. Format/BibTeX never publish maps.

The native Xe `dviclose` site is reached after actual final XDV postamble/flush.
Only its WASM branch calls the checked internal FILE closer. The private copied
sink closer returns its real IO result to native dviclose; all accepted shared
sink sources stay untouched. Actual native return, valid checked close, complete
raw postamble, consistent XDV7 header/postamble unit/mag/page count and bounded
output/log observations must all agree before sealing. No caller-exported finish,
seal, page or successful-close authority exists. Raw bytes remain canonical
uncompressed upstream SyncTeX1, <=1048575, with the unchanged ABI65536 token/copy
protocol. `oc_xe_maps_abi()==1` identifies this explicit new producer capability.

One attempt is consumed across LaTeX/INITEX/BibTeX, including failures, with a
non-overflowing latch. Entry is set once, ordinal is positive uint32, repeated or
ineligible calls revoke access. Actual failed-after-shipout, postamble/cap/log
failure, bad config/token/copy, default-off/off/user synctex assignment, classic
BibTeX, fresh INITEX and physical cancellation controls are exercised. A valid
XDV/PDF can remain usable while optional mapping is absent; no earlier map is AUX.

## Dependency and build proof

Historical stamps cover only TU source/argv, not included headers. They are not
sufficient to reuse this cache. `build-map-deps.py` freshly compiles all563 actual
retained dependency units with the current headers/compiler, records actual -MD
header hashes and compares every archive member byte. All seven retained archives
match: ICU common196/i18n240/stub1, HarfBuzz2, FreeType40, Graphite28 and Xpdf56.
Only after that proof are unchanged archives reused. No upstream Makefile is
executed; retained CMake metadata/verbose command records are finite recipe data.
`build-maps.py` verifies that complete proof and current header/source/archive
hashes, then compiles all28 selected Xe engine/glue/runtime units fresh.

Use fresh private outputs and a writable private copy of the already supplied SDK
cache with EM_FROZEN_CACHE=1. Build logs/commands, headers, objects, maps, native
format and candidates are private artifacts, not committed generated resources.
Native FS/resource/log/memory/shell/network limits remain the existing Xe policy;
new raw validation additionally withholds a map for >8MiB XDV or >256KiB log.

## Converter capability and coordinates

`native/tex/dvi-engine/build.py --xdv-geometry` is explicit **ABI3**, not ABI2
widened in place. Default ABI1 and `--geometry` DVI-only ABI2 are preserved.
ABI3 measures only the actual canonical-unit XDV7 route. Unknown versions/units
and unsafe/singular/dynamic states yield explicit unsupported null matrix/box;
>512 pages have no successful geometry prefix. Ordinary PDF conversion remains
usable where it otherwise succeeds. The usual131072-byte/512-page and private
measured-state/no-finish-export rules are unchanged.

`converter-overlay.py` reuses accepted native BOP/resolved-extent/special parser
hooks read-only, changing only the explicit native XDV7 domain. It captures the
actual native postamble units/magnification, actual writer BOP matrix and resolved
native writer extent, not a PDF-derived transform or copied PDF box. Native
PDF close/success/quota/once-only/token lifetime governs the optional JSON.

For the pinned Xe XDV hook, raw positions use TeX sp, `Output:xdv`, Unit1,
X/Y Offset4736287. Let B=72/72.27/65536, m=native header mag/1000, U=actual native
DVI-unit conversion, O=4736287*B and R=U/(B*m). The pinned query scales positions
by m but **not** preamble offsets. For actual native BOP M=[a,b,c,d,e,f], emit
`[aR,bR,-cR,-dR,e-aRO+cRO,f-bRO+dRO]`. The inverse image of the native writer
extent is writerPageBoxBp. This composes the actual Xe/query/converter contracts;
no extra one-inch/page-height/identity transform is inferred by the consumer.

These coordinates are unrotated raw default PDF space, not CropBox/intrinsic
rotation/display/CSS or physical millimetres. Root validates and binds the exact
copied map/XDV/PDF hashes plus trusted selected engine pass; converter ordinal is
not finalPass. Missing accepted Xe geometry must not gain legacy guessed identity
navigation. Do not remove the renderer's global zero-MediaBox-origin guard.

## Evidence and explicit limits

The independent fixture oracle decodes actual Flate/ObjStm/Type0 Identity-H /
embedded TrueType/ToUnicode CID text and page operators BEFORE map/geometry are
loaded. Actual word baselines and native CLI/WASM forward/inverse checks cover
root, source-owned included boxes and local class/style boxes, layout/content
changes, mag1200, genuine crop and rotations0/90/180/270. Numerical rounding
threshold0.003bp is a fixture serialization/query precision bound, not a thesis
compliance tolerance or glyph-ink measurement. Native unboxed-inline first-glyph
inverse provenance retains an explicit counterexample; no token-perfect claim.
Some magnified raw glyph points may lie outside crop; no visible click claim is
made there. CSS/drawn-page/browser acceptance is root-owned and unrun here.

Actual native writer DVI/XDV page initialization still uses MediaBox origin0,0.
Margins/crop, generic page dictionary injection or a rewritten PDF do not prove
supported nonzero/negative writer origins. The unrelated standalone MetaPost
bounding-box path has no this-producer XDV/map provenance. That hard cell remains
OPEN, along with genuine PDFium renderer acceptance if its pair is not supplied.

Exact-byte tests freeze fixture wall clock before Emscripten; monotonic timings
remain real. New on/off/default maps produce identical complete XDV/log/AUX.
Legacy/new-format XDV and AUX are identical; full logs retain explicit differences
in genuine format creation stamp and string/pool capacity. They are NOT normalized
away or called an exact old-format log match. Old default source/format behavior
is separately preserved; a new format ABI is not silently admitted as the old one.

No full Xe/font/thesis compatibility, source/PDF browser workflow, physical PDF
facts, R2/MVP completion, license/adoption or runtime release is implied.
