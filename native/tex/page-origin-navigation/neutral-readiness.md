# Typed native package navigation

The opt-in neutral1 derivatives extend the current-lineage origin candidates.
P13/P14, old query bytes, formats, raw map and worker/resource guards stay intact.
Only the separately pinned query uses area64 arithmetic. Geometry retains its
existing schema1, native measured matrix and inverse writer extent.

DVI/Xe witnesses come from actually executed native handlers and their actual
parsed PDF objects. Bounded direct metadata, view mode, destinations, outlines
and Link/GoTo/URI annotations are checked by type and complete consumption.
DeviceGray/RGB/CMYK operations inspect actual native color state/depth. Every
accepted channel must preserve actual native CTM and save depth. Unknown
specials, opaque objects, programs, bad types/suffixes, ambiguous dictionaries
and prior unsafe state remain refused. The pinned native configuration handler
and prescan both ignore configuration specials; its witness reflects that actual
behavior. A typed numeric major-version handler replaces an unrecognized native
dispatch while preserving the actual prescanned PDF version.

Lua witnesses are scoped by the actual native colorstack, Link/annotation and
catalog writers. The exact consumed buffers are bounded and fully validated:
device color operators, inert Link/URI attributes and catalog PageMode only.
Color validation never grants a raw literal caller permission. Empty color pops,
generic objects/actions, arbitrary literal/programs, unrecognized dictionaries,
forms and old unsupported transformations retain refusal. No unsafe latch is
cleared. Native witness functions remain private; only neutral ABI getters are
exported. This does not advertise arbitrary PDF-program or package support.

Lua additionally requires `oc_lua_neutral_abi()==1`; both converters require
`oc_dvi_neutral_abi()==1`. All current-lineage capabilities in
[current-lineage.md](current-lineage.md) remain required. Query ABI/schema1 must
pair the separately pinned `sq_area64_abi()==1` module. Old capabilities alone
never imply these new permissions. No private proof/seal function is exported.

`build-neutral-luahb.py` re-links its exact frozen origin parent before changing
only pdfgen, pdfliteral and pdfcolorstack archive members and adding the bounded
validator. Its manifest records complete ordered archive-member hashes, actual
source/header closure and unchanged linked inputs. `build-neutral-converter.py`
derives the frozen origin recipe, adds actual native handler hooks and preserves
DVI font semantics. Fresh independent builds reproduce all final bytes.

`run-current-corpus.py` accepts explicit runtime, Lua/DVI/Xe/query/E1 components
and a fresh results directory. It runs all eight unchanged package/biblatex
cases through52 actual phases, including genuine native BibTeX and generated
BLX carry, then checks16 independently selected E1 root/include glyph points
against exact native inverse filenames/lines. `check-current-forward.cjs` also
requires DEFAULT native forward boxes to contain those same16 glyph points,
with .01bp native writer-rounding tolerance and no candidate picking. All eight
PDFs and selected raw maps remain byte-identical to the prior origin-only
controls. No source, font, bibliography, PDF or map substitution is used.

Further actual checks pass:26 DVI/Xe and16 Lua typed-channel positive/negative
cases; all54 existing origin-domain assertions;13 current inherited-root and
P14 legacy comparisons; all21 Lua semantic-budget controls; nine current origin
scenarios with independent PDF/exact-line query oracles; old/new capability and
private-export controls; and actual native cancellation with fresh current-package
recovery. The historical cancellation recovery helper still has its older raw
filename suffix assertion; it remains unchanged, and its failed pilot is retained.

These are native checks. Closed profile15 admission, source revisions/UTF-16
selection, browser highlight geometry, actual online/cold-offline acceptance and
release remain master-owned. pdfTeX retains its existing zero-origin mapping.
Opaque RTL ActualText literals, general raw programs/forms/inherited attributes
and native map precision limits outside these proven fixtures are not newly
supported or silently normalized.
