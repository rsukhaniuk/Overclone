# Native graphics1 source-navigation variant

This package addresses the unchanged ordinary portable PNG/graphicx multi-file /
BibTeX fixture, not a new renderer, source scanner or application manager. It
never changes P8/P9 assets/pins/defaults or the accepted ABI2/3/5 recipes in place.
Root chooses a new closed profile and performs actual browser/offline acceptance.

## Actual diagnosis before policy edits

The exact P9 raw maps exist and root queries succeed, but all3 actual native
sidecar pages are unsupported/out-of-domain. The root product-worker VM runner
is reused for complete unchanged-P9 final-pass/BibTeX diagnostics. Native traces
localize the blanket unsafe events:

- DVI and Xe: `pdf:image ... (figure.png)` reaches the native image handler but
  the old unknown-special classifier has already invalidated all pages.
- Lua: typed native pdf_out_save emits `q` through generic pdf_literal; the old
  unconditional literal hook marks the whole run unsafe before native scale/
  raster/restore. Actual SyncTeX observations also occur inside that transform,
  so merely ignoring the unsafe hook or assuming q/Q balance is incorrect.

Failed browser receipts and intermediate diagnostic failures are retained. One
initial bare-FFI converter probe omitted project assets and therefore warned of a
missing PNG; it is NOT graphics acceptance. Subsequent positive tests include all
unchanged fixture files plus exact bundled PNG, verify a real192x192 raster draw
from actual PDF objects/operators, and compare root/include/citation points.

## Explicit new capability, unchanged old candidates

New build-only opt-ins are `build-converter.py --kind dvi|xe` and
`luatex-engine/synctex/build-graphics.py`. Each native variant adds the read-only
capability export `oc_dvi_graphics_abi()==1` / `oc_lua_graphics_abi()==1` on top of
base converter ABI2/3 or Lua ABI5. These do NOT authorize legacy-profile adoption.
Old binaries stay immutable; root must bind new component bytes and require the
new capability under a newly allocated CLOSED profile. No private observer,
finish, page, restore or seal authority is exported to JavaScript.

The accepted converter build.py/oc_dvi.cpp/.h remain unmodified. The new recipe
verifies their exact preimages and builds a private source overlay. The existing
DVI/Xe overlay scripts change behavior only with explicit `--graphics`; without
it their generated C remains byte-identical. Lua's new native observations are
compiled only with OC_LUA_GRAPHICS; the old SyncTeX TU recompiles byte-identically
with that flag absent. No format/node/string layout changes: the exact approved
P9 formats are reused with source/header/ABI proof, never silently regenerated or
relabelled. Unchanged archives/objects are reused only under recorded input hashes.

## DVI/Xe: typed raster witness, not prefix whitelisting

Unknown specials are provisionally unverified until actual native dispatch
completes. They become unsafe at special end unless a complete private native
witness verifies the operation. Earlier unsafe state is never cleared.

Only the actual parsed pdfm raster image path may provide this witness. It must
resolve an actual IMAGE XObject (not external PDF/form/PS), have no custom PDF
dictionary, hidden draw or trailing program, and complete its actual native
image draw. The draw observes actual gsave/grestore return values, before/after
native stack depth and complete CTM equality, plus finite/invertible final local
matrix and valid native clip extent. Parent source-coordinate state is restored
by observed native operations, not inferred from image names, dimensions or q/Q
text. Unknown programs, malformed images and dictionaries still refuse geometry.
Actual units/BOP/extent/page-close/success/token/cap authority remain unchanged.

## Lua: native typed state and true native coordinates

Private native hooks observe actual pdf_out_save/restore and pdf_out_setmatrix.
A bounded64-entry ledger verifies native depth changes, matching actual saved
position, native matrix stack restoration and empty state at page completion.
The complete actual expanded matrix bytes must be exactly four finite PDF
signed-decimal tokens, positive axis-aligned scale; no exponent/hex/NUL/program
suffix, singular/reflected/sheared domain is accepted. A one-call private marker
permits only those typed native emissions through pdf_literal. Generic TeX/Lua
literals, colorstack programs, arbitrary objects, forms, callbacks or attributes
retain their previous conservative refusal. No raw string prefix is whitelisted.

For SyncTeX records emitted while the actual native matrix stack is active,
actual native matrix entries transform the actual native position and box/rule
dimensions into the page writer frame with the pinned native rounding rule.
This is a native coordinate observation, not a map inferred from source/log/PDF
text. Untransformed hooks remain unchanged. Rotation/shear/reflection and unsafe
state remain unsupported because canonical axis-aligned SyncTeX boxes cannot
honestly represent those domains here. Raw canonical SyncTeX1 and query ABI1 are
unchanged; existing page geometry still comes from actual native writer state.

The independent oracle additionally found Lua's absolute native project prefix
blocked a captured `chapter.tex` forward query. Only this opt-in adapter translates
fixed `/work/project/` and its literal bootstrap `./` to the COMPLETE captured
relative spelling before upstream record creation. It never strips basenames,
resolves traversal or normalizes Unicode; runtime filenames remain runtime names.
No query/path-admission guard is widened.

## Validation scope and boundaries

The original portable main-latin/main-unicode/chapter/bib/xbb and bundled PNG bytes
are unchanged. Actual native finite passes, classic BibTeX and AUX churn retain
source/input/output hashes. An independent fixture-only PDF byte oracle decodes
actual Flate/ObjStm/fonts/ToUnicode/text matrices and raster draws BEFORE loading
maps/geometry, then checks real native root/include/citation forward/inverse,
page dimensions and native matrices. It is not a product PDF parser or physical
measurement rule. Numerical tolerance is PDF/query serialization precision only.

Additional native negatives cover raw balanced/unbalanced PDF/PS programs,
unknown specials, image dictionaries/tails/singularity, page attributes/UserUnit/
MediaBox, typed matrix suffix/exponent/short/singular/reflection/shear, missing or
misplaced restore, forms, failure/token/copy/quota and stale-instance lifetimes.
The native engine itself fails unmatched save at page end and exposes no map.
Actual worker termination during native work and fresh recovery are exercised.

P9 worker hard-coded component hashes correctly reject new variants. The root VM
runner does not bypass those guards or claim new-profile adoption. Native variant
FFI/oracle evidence is separate from unchanged-P9 product-worker diagnostics;
root owns new pin/profile binding, C#/Node integration and published browser /
cold-offline acceptance. Nonzero/negative MediaBox origins, arbitrary programs,
unsafe coordinate domains, >512-page geometry, existing inline precision and Xe
non-BMP filename gaps remain open. No physical-rule/full-parity claim is made.
